# 转个弯 · 火车中转规划

本地可运行版本。Python 3.10+，仅使用标准库，无需安装后端依赖，无需铁路账号。网页适配电脑与手机。

当前正式版本 **v1.1.0**，包含本地矢量地图选点、主要客运站突出显示与查询进度地图。历史版本 **v1.0.0** 保留在同名 Git 标签，界面仍按“行程 → 偏好 → 查询进度 → 路线结果”四步推进。具体变更见 [CHANGELOG.md](CHANGELOG.md)。

## 地图选点

第一步左侧纵向填写出发地、目的地和日期，右侧打开大地图。全国视图先显示主要城市，滚轮/双指放大后增加地级城市、省直辖县级入口与下属县级市；按行政层级区分点大小。昆山在全国视图隐藏，点击苏州显示包含昆山的本市车站；天门作为独立入口。

点击城市缩放并突出显示本市车站，另以棕色显示距本市站点 45 公里内的最多 40 个邻近站。点击车站或列表后明确确认出发地/目的地；也可选择城市范围查询。地图只是输入方式，不扩大原有上游城市查询的覆盖承诺。未确认的点选、拖动和缩放不修改条件。确认出发地后总是转到目的地选择，即使保留有旧目的地，也需明确确认。选城与两地取景使用约 650 毫秒的可中断过渡，选定两地并完成取景后用 1.1 秒绘制方向箭头，支持地图与文字、交换、历史和分享条件同步。地图数据加载失败可继续文字输入。

地图与 D3 均随程序本地提供，无地图 Key、瓦片服务或在线 POI 请求。站点坐标为 OpenStreetMap 与 12306 站码/名称匹配的快照，缺失坐标的站继续使用文字输入；确切覆盖数见 `web/map-data/coverage.json` 和地图“数据与覆盖”。城市范围采用 2026-10-18 获取的 369 个完整 OSM 行政边界；县级细节仍来自 2017 历史资料，行政树为 2023，全国轮廓为 2019（直辖市已同步更新）。城市归属按完整边界判定，县级细节缺失不再造成城市缺块。所有来源与数据库分发许可见 [MAP_SOURCES.md](data/MAP_SOURCES.md)。余票与票价查询仍需联网。

地图支持缩放按钮、全国/两地视图、键盘方向键和加减键、城市/车站搜索、手机全屏布局，尊重系统减少动态效果设置。手机已做浏览器模拟验证，双指手势、软键盘和安全区还需真机验收。

## 界面流程

1. 行程页：填写出发地、目的地、出发日期；最近查询保留为次要入口。
2. 偏好页：选择推荐方式和时间要求；选择夜间卧铺后显示休息时长、凌晨偏好。高级选项默认折叠，包含中转、席别、预算等，收起后显示已设置数量。
3. 查询页：显示真实任务阶段和进度，可停止查询或返回查看条件；完成后自动进入结果页，失败则留在本页重试。
4. 结果页：简洁路线列表，逐段详情在卡片内展开，保留对比、复制、分享和购票链接。无结果时同样进入本页并提供修改偏好入口。

顶部步骤可以切换，返回查看不清空条件或取消查询。实际修改条件才取消正在运行的查询并作废旧结果；迟到的创建响应和查询结果不能覆盖修改后的状态。结果作废后，查询页明确提示条件已修改。浏览器前进/后退同样支持步骤切换。

已有分享链接可在加载或刷新页面时恢复条件，先展示第一步，不自动发起查询。

## 启动

从仓库取得代码：

```powershell
git clone https://github.com/aNother1332/railway-planner.git
cd railway-planner
```

在本目录运行：

```powershell
python app.py --port 8765
```

浏览器访问 <http://127.0.0.1:8765>。按 Ctrl+C 结束服务。

可运行 `python app.py --version` 查看版本号。程序版本统一维护在 `version.py`。

Windows 也可以双击 `启动转个弯.cmd`：它会打开浏览器并在命令行运行服务。命令行关闭后服务结束。

需要从同一局域网的手机访问时，手动运行 `python app.py --host 0.0.0.0 --port 8765`，再用电脑局域网 IP 打开。默认只监听本机；尚未完成手机真机触摸、软键盘与安全区测试。

## 已实现

- 城市或精确车站查询，中文、拼音或简拼建议；选择“XX站”会锁定车站，城市级查询按上游返回同城车站并过滤。
- 最早出发、最晚到达、连续 1—3 个出发日期；完整时间窗口最多 5 天。只查询进入预售期的路段。
- 直达对照、最多一次中转：官方首批候选 + 有限枢纽扩展，包含区域铁路枢纽。
- 均衡、价格优先、总耗时、最早到达、夜间卧铺；总耗时和最早到达分别排序。
- 夜间卧铺模式要求一个卧铺路段与 22:00—次日 08:00 的连续重叠达到所选时长（默认 6 小时），不是实际睡眠保证。
- 卧铺休息达标后，优先减少白天行程，再比较到达时间和价格；不会仅因多几分钟卧铺休息就优先推荐更贵、白天占用更多的行程。
- 中转城市/车站优先或必经、排除中转城市、停留时长、最短换乘、最长等待、可选同城换站。
- 凌晨换乘区分“尽量避开”“严格避开”和“不限制”。默认尽量避开：满足卧铺休息要求、5 点后到站、6 点后接续、同站且等待不超过 2 小时的路线可以保留，明确标注早到；严格模式不放宽 0—6 点限制。旧分享链接显式设置 `avoid_early=true` 时仍按严格模式处理。
- 成人席别选择、混合席别、预算；硬座和无座默认关闭。未取得可靠查询价的路线不计入精确最低价，也不能满足硬预算。
- 每段余票和按实际日期的查询票价；使用购票页的 `leftTicket/queryTicketPrice`，不使用 `queryAllPublicPrice` 代替执行查询价。
- 逐段日期、车次、席别、票价及查询时间；路线详情、最多三条对比、复制行程、打开官方购票查询。
- 本机最近 8 次查询、查询条件分享链接。分享后需要重新查询，不传播历史有票承诺。localhost 链接只在运行服务的电脑上可用。
- 异步查询进度、取消查询、失败/部分结果/空状态。

## 请求与数据边界

首次匿名会话初始化；会话复用；相同请求合并；余票与价格缓存 45 秒；所有上游请求全局串行且间隔至少 0.3 秒；单次最多 84 个上游请求、约 110 秒预算（正在进行的网络请求最多再等 10 秒）；最多两个本地查询任务并行。

遇到验证页面、异常返回或 HTTP 错误会暂停上游访问；没有代理轮换、验证码处理、账号托管、抢票、自动购票或任何绕过访问限制的机制。

每次搜索最多核验 36 条候选，枢纽和日期扩展也受预算限制。枢纽候选同时覆盖沿途走廊和目的地来向附近的接续城市；核价前先轮流覆盖不同城市、不同前序车次，再为同一前序车保留最多两个接续备选，避免同车不同接续占满名额。候选选择覆盖快速、普通列车与夜间路线，但不是穷举。所谓“本次已核验最低价”只在显示的、已有可靠票价和有票状态的结果中成立。范围、未完成原因和缓存情况会在页面列出。

同城换站至少预留 120 分钟，但未接入实时市内交通。默认同站预留 45 分钟是产品的筛选阈值，不是对所有车站的换乘保证；尚未接入车站专属换乘时间库。

无票的具体候补资格尚未逐车次核验，因此界面只称“无票或待核实”，不会将无票全部标成可候补。同车换座、多人同行、学生/儿童等优惠票、邻近城市扩展、登录态采集和公开部署不在本版。

官方网页内部查询接口不等同于获得第三方开放授权。当前验证了本机环境可获取数据，没有上游 SLA；公开运营前需进一步核实数据使用条件、持续可用性、容量与部署安全。

## 文件结构

```text
app.py              本地 HTTP API、任务管理和静态页面
domain.py           时间、席别、硬约束、路线与排序
provider.py         车站、会话、缓存、限速及查询票价适配
planner.py          直达、候选枢纽扩展与逐段核价
web/                无框架 HTML / CSS / JavaScript
data/stations.js    从官方公开站名资源取得的车站快照
tests/              离线规则与数据层测试
```

代码为本项目独立编写。研究参考 `drfccv/mcp-server-12306` 的接口组织，没有直接复制其客户端实现；车站数据来源为 12306 官方公开资源，快照取得于 2026-10-17。

## 本地 API

- `GET /api/config`：中国日期、预售期边界、站点数。
- `GET /api/stations?q=武汉`：城市/车站建议。
- `POST /api/search`：创建查询任务，返回任务 ID。
- `GET /api/search/{id}`：进度与最终结果。
- `POST /api/cancel/{id}`：请求取消。

输入为中国当地时间。示例：

```json
{
  "origin": "北京",
  "destination": "柳州",
  "earliest": "2026-10-18T18:00",
  "latest": "2026-10-20T20:00",
  "mode": "sleeper",
  "via": "桂林",
  "via_mode": "must",
  "min_sleep": 360,
  "depart_days": 1,
  "seats": ["O", "3", "4", "F", "I", "J"]
}
```

示例日期会过期，请使用当前预售期内的日期。


## 车站显示与查询地图

地图按客运展示优先级调整标点大小、名称避让顺序和本市车站列表。配置为 `data/station_display_priority.json`，生成器将其写入站点数据的 `displayPriority`。重点站、代表性枢纽与其他已定位站共三档；这是界面展示规则，未作为铁路官方特等/一等站等级发布，也不改变任何车次或路线筛选。

查询页使用同一份本地地图，无新增地图服务。`GET /api/search/{id}` 的 `events` 为最多 256 条按序号递增的事件：`hub` 包含组合中的站码和城市；`verify` 包含实际进入核价候选的车站顺序。前端去重后显示城市与候选箭头；箭头仅示意候选地点关系，是否有票、核价是否成功以最终结果为准。现有只接收两个参数的进度回调保持兼容。

新增交互检查：`node tests/browser_progress_map.cjs`，与原浏览器测试使用相同的 `PLAYWRIGHT_MODULE` 配置。

查询进度地图按两端及已发现的中转城市自动取景，新增地点时平滑调整范围，保持标点大小及边缘留白；无需手动缩放。
